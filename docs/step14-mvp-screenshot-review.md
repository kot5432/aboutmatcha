# STEP 14｜実機スクリーンショットの確認と応募PDF用アセット要件

記録日：2026-11-11
状態：ユーザー提供の**スマートフォン画面スクリーンショット3枚を目視レビュー**。スクリーンショットは実機ブラウザーでの表示の証拠であるが、全機能・全端末での動作テストや製品画像の使用権限を証明するものではない。ユーザー申告：左右にスワイプして商品移動可能。

## 1. 実際の画像で確認できたこと

- トップバーのブランド表記「MATCHA ROUTE」「FIELD NOTES / DROP 01」。
- 見出し「まだ知らない、抹茶のかたち。」、補足「5つの抹茶スイーツをめぐる。」。
- 「発見型／一覧型」の表示切替ボタン。
- 「食べてみたい」保存一覧への入り口と件数バッジ（画像では「4」。**これはスクリーンショット時点の端末ローカル状態でありユーザー4人等の統計ではない**）。
- 大きな抹茶バスクチーズのイメージイラスト。「ILLUSTRATION · CONCEPT VISUAL」の明記。
- 商品名「抹茶バスクチーズ」、店舗名「world tea labo 淀屋橋」。
- 開示前「タップして、発見ポイントを見る」と開示後「DISCOVERY POINT／抹茶とチーズ、どちらが主役？／チーズケーキに抹茶を重ねた、味の組み合わせに注目。」の状態違い。
- 「保存済み」ボタンと「詳細を見る」ボタン。
- 下部に「左へスワイプで次へ／右へスワイプで前へ」、前後商品へのナビゲーションがある。
- 実際の一覧画面、商品詳細モーダル内部、保存済み一覧内部、別の商品にスワイプした直後の状態は**未提示**。スワイプで移れることは本人報告、静的コードにも処理あり。
- 画像は縦長のブラウザー画面キャプチャであり、Chrome等の上部アドレスバーや黒余白は応募PDFには不要。画面内のデータ・状態を変えて捏造しない範囲で切り抜く。

## 2. 応募PDF P4に採用する見せ方（提案）

**大見出し：「見つける、魅力を知る、保存する。」**

- 左：実スクリーンショット（商品イラスト・商品名・タップボタンが見える状態）。幅を大きく確保。
- 右上：開示後の「DISCOVERY POINT」を切り抜き拡大。「この商品ならではの特徴に出会う」と短く説明。
- 右下：ハート保存済みの部分を切り抜いて説明。「気になった商品を後から見返せる」。
- 図の下に小さな移動矢印と「左右スワイプでも別の商品に出会える」。
- 注記：「開発中の5商品デモ画面。商品情報は仮・画像はイメージイラスト。正式商品掲載・公式購入先への案内は今後整備。」
- 元の画面の「まだ知らない、抹茶のかたち。」を、現在動作中の初回10商品テーマ「まだ知らない、抹茶の10のかたち。」と**混同させない**。初回テーマは事業構想としてP5に置く。
- スクリーンショット上の「4」は保存済み件数であり、利用者数や購入数ではない。指標に転用しない。

## 3. この画像があれば十分なこと／次に必要なもの

**この3画像で十分説明できること**
- Webの見た目・基本の発見体験（商品表示、開示、保存ボタン、移動案内）
- ショップ名・商品名・大きな視覚が表示されていること
- 編集方針のトーン（深緑、生成り、イラスト）

**追加でもらえるとよい画面（優先度順、制作上の任意の改善）**
1. 「食べてみたい」を押した**保存済み一覧の内部**：保存の成果が確認できる。
2. **「一覧型」の内部**：発見型との用途の違いを示す補助資料に使える。
3. 「詳細を見る」の中身：商品情報の内容と参照リンク表示を確認。
4. 別の商品へスワイプした画面：商品の多様性の確認。動画は必須ではない。

P4のスペースが限られるので、**これらの画面を全て応募PDFへ並べる必要はない**。まず提供済み画像の3状態を使ってPDFのレイアウトを組める。追加素材が入る場合は補足説明や選び直しを検討する。

## 4. 実装面での別途確認事項（応募資料で確約しない）

- 現在の5商品デモのリンクはInstagram元投稿であって、公式通販・決済・成果報酬への導線ではない（2026-11-11ソース静的確認）。
- 保存はブラウザーlocalStorage。ログイン同期・共有保存ではない。
- 複数テーマ管理、10商品正式掲載、POP-UP開催情報、商品別QRは将来構想。
- デモの情報・イメージイラストは正式な商品画像や実食レビューではない。
- 商品写真の使用条件と公開商品情報の権利は別途確認。

## 5. デザイン改善の候補（緊急ではない）

- スマートフォン画面を縮小した際の小さな英字装飾（FIELD NOTES、DROP 01、ILLUSTRATION）を読ませるのではなく、資料側で意味を補う。
- 「タップして発見ポイント」の開示前後が主要価値なので、この差が大きく見える構成にする。
- 保存済み一覧が確認できれば「保存→後から見返す」の説明がさらに確実になる。
- 「一覧型」表示は発見型の補助機能。資料の中心を「検索・一覧機能」に置かない。

## 6. 提出用素材の扱い

- ユーザー提供の画像を**応募資料のMVP実画面資料**として使う予定。画像の取り扱い・他者の権利がある素材の公開利用については提出前に点検する。
- スクリーンショット内に実在ショップ名・仮のイメージイラストが同時にあるため、**正式な商品写真・公式監修済み画面であるとの印象を与えない**。
- 元画像の名前・GitHubバイナリ保存場所は今段階でコミットしない。プランニング文書のみコミットし、ユーザー画像を無断で公開リポジトリへアップロードしない。
