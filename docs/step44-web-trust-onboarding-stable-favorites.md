# STEP 44｜Webの初回案内・掲載情報・保存IDを改善

更新日：2026-11-12
状態：**GitHubコード更新・JavaScript構文確認・保存移行ロジック4ケース成功。Vercel公開ページの新デプロイ・実機ブラウザ操作は未確認。**

## 目的
ビジコンの提出用Webデモの基本体験を壊さず、①初めて利用する人が迷わない ②販売情報を誤認させない ③商品を追加・並び替えても保存がずれない、を改善する。最新応募資料v19（9ページ）はこの作業では変更していない。

## 実装した内容
対象：https://github.com/kot5432/matcha の `index.html`

### 1. 初回案内
ホームのヒーローと発見型・一覧型切り替えの間に短い説明を追加。

> 楽しみ方｜3つのステップ
> ① 一品ずつ見る → ② タップして発見ポイントを知る → ③ 気になったら♡で保存。

購入を強制しないこと、各商品の入手情報は「詳細を見る」にあることを明記。チュートリアル用の画面遷移は追加しない。

### 2. 掲載情報を正確に説明
フッターの古い「現在の販売状況、価格、在庫、取扱店舗は未確認です」を修正。
前のSTEP 42で公式の商品情報を一部確認できているため、**一部は確認済みだが、現在の販売・在庫・購入可能性は保証しない**という表現へ更新。
5点の画像が実写の商品画像でなく仮イラストであること、外部リンクには公式情報とInstagramの紹介元があること、サイトでの決済・成果報酬がないことを明示。

### 3. 保存を固定商品IDへ移行
以前の保存キーは `matchaSaved` で商品配列の0〜4番の数値を保存していた。今後商品の順序を入れ替えると、別の商品が保存されているように見えるリスクがあった。

- 5商品それぞれに固定 `id` を追加：
  - `matcha-basque`
  - `matcha-opera`
  - `matcha-brulee-crepe`
  - `matcha-daifuku-pancake`
  - `matcha-ice-bar`
- 保存は新キー `matchaSavedV2` へ商品ID文字列の配列で行う。
- 初回読み込み時、V2キーが存在しなければ従来の `matchaSaved` を**読み取って変換**し、可能ならV2へ保存。旧データを消さない。
- 読込時に有効なID以外と重複を除く。保存失敗時も画面の使用は継続。
- 発見型・一覧型・商品詳細・保存済み一覧の状態表示とボタン挙動をID基準に更新。
- 過去の保存一覧の順序も変えない。

### 4. 細部の改善
- HTMLの `meta description` と検索結果向けタイトルを改善。
- `savedrow` に折り返しと幅指定を追加し、保存済み一覧の「詳細を見る」「保存を外す」の操作領域の窮屈さを緩和。
