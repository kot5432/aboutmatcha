# STEP 10｜応募添付PDF（説明なしで読める9ページ）構成案

作成日：2026-11-11
状態：**完成原稿ではなく、事業再設計に整合させた制作指示・文章草案**。PDFは未制作。完成版には実画面・権利確認済み画像・商品出典を反映する。
基準：docs/step10-business-redesign.md

## 1. 役割と読み手

これは本人が口頭発表するスライドではなく、**書類審査で単独閲覧される応募添付PDF**。審査員が資料だけで「好きの原点→誰への価値→具体体験→丸井と組む意味→事業性→現在地」を理解できることを第一にする。

- 9ページを第一候補とするが、応募先のページ数・容量制限が優先。
- 各ページ：結論型タイトル1つ、根拠や具体説明を2〜4単位、主役となる実画面／写真／図1つ。
- 「図だけ」「キャッチだけ」のページにしない。図には必ず利用者が読める短い説明を付ける。
- 商品は実写真の権利が確認されたものを使用。掲載未許諾の候補を確定商品として扱わない。
- 装飾的なAI生成商品写真は、実商品・実施済み店舗の根拠と誤認されるので優先しない。
- 章をまたぐ重複を減らす。6ページは実施内容と丸井の協業、7ページは誰にどう価値が生じるか。別の役割にする。

## 2. 各ページの完成文章に近い草案と図

### P1 表紙／事業を一文でつかむ

**見出し：知らない抹茶に、会いに行こう。**
**サービス名：MATCHA ROUTE**

本文候補：
「まだ知らない抹茶のおいしさや魅力を、テーマごとに発見できるWebサービス。丸井グループの店舗との連携により、Webでの発見を実物との出会いにも広げる事業を提案します。」

ビジュアル：利用許諾済みの実在抹茶スイーツ写真1〜3点、サービス名とコピー。フッターに「Web MVP開発済み／店舗連携は構想」。表紙でサービスを抹茶販売店と誤認させない。

### P2 原体験／なぜ自分が取り組むか

**見出し：私の「好き」が、誰かの「おいしい」に。**

本文候補：
「小学生の頃、ほかの甘いものやアイスはあまり好きではありませんでした。でも、抹茶アイスだけは特別。今も濃厚な抹茶が大好きです。ある日、抹茶があまり好きではない友達にお菓子を渡すと、『おいしかった』と言ってくれました。自分の好きなものの魅力が伝わる喜びから、もっと多くの人に届けたいと考えました。」

ビジュアル：原体験の2段階（抹茶アイスが好き→友達からの「おいしかった」→発見の場を作りたい）。友達が抹茶好きになったとは書かない。

### P3 想定ユーザーと課題仮説

**見出し：抹茶が好きでも、まだ知らないおいしさがある。**

本文候補：
「最初に届けたいのは、新しい抹茶スイーツにも興味がある抹茶好きの人。SNSや通販でも商品は見つかります。MATCHA ROUTEはそれらを否定せず、抹茶に絞ったテーマと編集された紹介を通じて、自分から商品名を検索しなくても出会える楽しさを増やします。」

図：左「好きだけれど、何を探すか決めていない」→中央「テーマ別の発見」→右「気になる一品を保存」。小さく「需要は今後検証する仮説」。競合より優秀／必須の社会課題と断定しない。

### P4 実際のWeb体験（最重要）

**見出し：写真から出会い、魅力を知り、気になる一品を残す。**

本文候補：
「商品を一つずつ写真で紹介し、DISCOVERY POINTで素材・食感・作り手などの特徴を伝えます。気になる商品は保存でき、現在の試作では元のInstagram投稿を確認でき、公式購入先への案内は今後整備します。買わなくても楽しめる発見体験です。」

図：**大きい実MVP画面1枚**（DISCOVER）＋小さい実画面2枚または機能切り抜き（DISCOVERY POINT／WISHLIST）＋短いラベル。複数のスマホ画面を小さく並べただけにしない。

状態注記：「基本機能は開発済みとの本人確認。掲載データはデモの場合があり、現画面の再確認が必要」。現状の5商品デモを10商品公開済みと記さない。デモのリンク先は元のInstagram投稿であり、公式購入先ではない。スクリーンショット・実装はPDF作成前に確認する。

### P5 テーマ編集と具体的な3商品例

**見出し：同じ抹茶でも、出会い方はいくつもある。**

本文候補：
「初回テーマは『まだ知らない、抹茶の10のかたち。』。濃厚さ、食べる体験、小さな和菓子など、異なる魅力をもつ商品を紹介します。珍しさだけを選ぶのではなく、『おいしそう』『食べてみたい』につながる魅力を大切にします。今後は『濃い抹茶が好き。』『今日のおやつは抹茶。』などにも広げる構想です。」

図：特徴の異なる3商品カード（例：抹茶テリーヌ／手作り最中／抹茶金平糖）。カードに商品名・一行DISCOVERY POINT・公式出典を付ける。**商品名／特徴／写真は公開前に検証・許諾。仮のイメージに実商品名を重ねない。** 初回10候補と正式公開済みを区別。

### P6 丸井グループとの協業（実行案）

**見出し：Webで見つけた「好き」を、丸井の店舗で体験する。**

本文候補：
「発見体験型POP-UPを提案します。DISCOVERY WALLでは許諾済みの10商品を写真や言葉で紹介。MATCHA SELECTでは条件が整った最大3商品を販売候補とし、商品別QRからWebの詳細・保存・次の発見へつなぎます。販売できない商品は『紹介のみ』と明示します。」

図：展示エリア（DISCOVERY WALL）＋販売候補（MATCHA SELECT）＋QR（WEB CONNECT）の空間概念図。図下にWeb→開催情報→来店、店舗→QR→Webの2本の矢印を簡潔に。

丸井との具体的協業依頼：「店舗・催事スペースの小規模実証可能性、館内案内、運営／販売条件の協議」。会場・無料提供・供給が決定したとは書かない。仕入れや食品安全の条件が整う前は、許諾を得た展示のみの軽量実証も検討。

### P7 「好き」から誰かの価値へ

**見出し：一つの「好き」が、利用者・作り手・店舗の接点になる。**

本文候補：
「利用者には、新しいおいしさを知り、気になる商品を選べる楽しさを。作り手には、商品やこだわりを初めて知る人との接点を。丸井グループには、Webからの来店と、店舗での体験がWebに続くきっかけを生み出すことを目指します。」

図：MATCHA ROUTEを中心にした3者の価値マップ。各者の下に検証指標を1つだけ置く（利用者：保存理由／作り手：商品ページへの関心／丸井：来店動機・QR利用等）。社会的インパクトや売上増加を実証済みと書かない。

### P8 ビジネスモデル（契約条件と費用を隠さない）

**見出し：発見を、継続できる事業へ。**

本文候補：
「Webは無料。商品に興味を持った人を公式購入先へ案内し、適法な成果報酬契約が成立した場合のみ報酬を得ます。POP-UPでは、販売主体・仕入れ・会場・人件費などの条件を決めた上で、一部販売による収益化を検討します。契約や売上の実績はまだありません。」

図：左 Web「発見→任意の購入先移動→契約・承認後に報酬」、右 POP-UP「展示→一部購入→原価・運営費を差し引く」。下段に必須確認「掲載権利・契約主体・供給・人員・衛生・費用」。金額の大きな予測グラフは載せない。収支の仮定は説明資料または注記に限る。

### P9 現在地／検証／丸井への依頼と未来

**見出し：小さく確かめながら、新しい「好き」を広げる。**

本文候補：
「現在、写真からの発見・詳細確認・保存を備えたWeb MVPを開発しています。次に実際の利用者の反応、商品紹介の許諾、テーマ更新の負担を確認。丸井グループと、店舗での小規模な展示・QR連携、条件が整った場合の一部販売を検討したいと考えています。」

図：3段階のロードマップ「Web MVP（開発済みとの報告）→利用者・編集検証（計画）→丸井との小規模実証（未合意の提案）」と、丸井への相談事項「場所／運営・販売の条件／効果の測り方」。

締めの一文：「抹茶の『好き』から、まだ知らないおいしさとの出会いを増やす。」

## 3. デザインと制作ルール

- 16:9横長を第一候補。応募先指定があれば従う。PDFは閲覧倍率を縮めて読めるか確認。
- 深緑 #214B38、抹茶 #7C9862、生成り #F7F4EA、本文 #252B27 を基調に。
- 見出し30〜36pt、本文18〜22ptを基本。注記14pt以上を目安にし、文字数とページ分割を調整。実画面の中の文字も読める倍率を優先。
- 各ページの文字を単純に削らない。**「結論＋具体例＋図＋必要な注記」**の順に組み、伝える内容を残す。
- 写真を多くするページはP1/P5、実画面はP4、図解はP3/P6/P7/P8/P9。P2は短いストーリー。商品写真を飾りとして全ページに敷かない。
- チャートは計測値がある時だけ。根拠のない市場規模、来訪者推計、売上増加をグラフにしない。
- 「開発済み」「検証予定」「丸井との協業構想」「仮定」を視覚的に区別。
- 実商品写真・ロゴ・引用には出典と利用条件を確認。店舗完成イメージには必ず「構想図」と表示。
- 2MBは以前記録された推奨値。**公式フォーム上で提出形式・容量・ページ条件を最終確認**し、画像圧縮などを調整する。

## 4. PDF制作の前に確認すべき3つ

1. **実画面**：現行MVPを実際に開いて、DISCOVER／DISCOVERY POINT／保存の画面を確認。画面に映る商品・画像がデモなのか実データなのかを明記。
2. **実商品3例**：事実の出典、写真利用条件、現在の入手可能性を確認。確認できなければ別候補を使う。
3. **応募条件**：応募年齢、添付容量・形式・ページ数、要項とフォームの最新状態を確認。条件不明のまま「応募できる」と断言しない。

## 5. 応募フォーム回答との対応

| フォーム | PDF上の主な対応 |
|---|---|
| ① 好き | P1・P2 |
| ② 熱量エピソード | P2 |
| ③ 事業概要 | P1・P4・P6・P8 |
| ④ 共感 | P3・P4・P5 |
| ⑤ 課題・意義 | P3・P7 |

フォーム文章の最新版は別途最終照合する。過去の7ページ草案や「珍しい商品だけ」という旧表現は制作用の最新版として扱わない。

## STEP 12追記：POP-UP・掲載実務の実現性（2026-11-11）

- マルイの一般出店サービスOMEMIEでは、通常POP-UPは原則最低7日間（一部店舗14日間）、2名以上のスタッフ確保、固定賃料の前払い、商談後最短90日からなどの条件がある。**従来の3日間・固定費7万円試算を実施可能な計画として載せない**。好きコンでの協業に同条件が適用されるかは未確認。
